# BabyCare 全面质量审查与整改

审查分支：`codex/comprehensive-quality-audit`。基线：`43b2161`。已 fetch 远端，当前基线包含 `origin/main` 的全部提交。

## 验收原则

保留「持续记录婴儿生活 → 理解规律 → 参考预测 → 减轻照护负担」的产品理念，以及 Soft Utility 2.0 视觉语言。

将“业内顶尖”拆成可验证要求：已有数据可升级和恢复；记录、暂停和跨日统计一致；提醒不会空转或误发；缺少数据时不制造确定性；主要操作可恢复；浅深色和男女主题可读；真机主要流程可完成。

参照 [Android 核心应用质量指南](https://developer.android.com/docs/quality-guidelines/core-app-quality) 的状态保留、稳定性、触控与对比要求，并参考 [Huckleberry 官方产品说明](https://huckleberrycare.com/) 的高频记录、规律洞察和照护减负方向。竞品说明仅用于确定评估维度，不能据此宣称本项目已达到同等质量。没有真实家长可用性研究、留存数据和多设备长期验证，不能客观证明“业内顶尖”。

## 产品能力差距与验证边界

- 家庭共享仍是“敬请期待”，不能视为已具备多照护者协作；同步服务、账号和冲突策略应作为独立产品项目设计。
- 预测为本地规则估计，需要持续记录与真实使用验证，不代表临床判断或确定的作息安排。
- API 28 真机用于历史升级与 MIUI 兼容；Android 15 模拟器用于补充新系统验证。模拟器不能替代最新平台、折叠屏和平板实机的长期验证。
- 旧计时记录只保存总有效时长，没有完整暂停片段；跨日统计按持续区间比例分配有效时长，保证分日合计守恒，不能恢复历史暂停发生在哪一天。
- 保存操作已验证配置重建期间防重复和完成结果单次消费；进程被系统杀死恰逢数据库提交的严格一次性写入，需要额外持久化操作标识，本次不宣称该边界已保证。
- 需要家长实际完成夜间单手记录、补记、切换宝宝和恢复备份等任务的可用性研究；本次工程审查无法替代该证据。
